# tagcode 동작 명세 (REA 정적 분석)

대상: `tagcode` Mach-O arm64, sha256 `1494994beb4d4fd3836cd4c173945f6d77189cf40b1f2c4747b22f5b22c93393`
분석 도구: REA + Ghidra 12.1.4

Evidence:
- E1 `ev_e3d3b04f…` list_procedures: 내부 함수는 `entry`(0x100000460, main)뿐이고, 외부 함수는 `_printf`, `_puts` 두 개
- E2 `ev_3c4753ac…` list_strings: `"code=%04u grade=%s\n"`@0x10000054c, `"PLATINUM"`@0x560, `"GOLD"`@0x569, `"SILVER"`@0x56e, `"BRONZE"`@0x575, `"usage: tagcode <text>"`@0x57c
- E3 `ev_64fe0708…` procedure_pseudo_code(entry)
- E4 `ev_5c1ae269…` procedure_assembly(entry)

표기: **[확인]**은 Evidence에서 직접 읽은 사실이고, **[추론]**은 그 사실을 해석해서 얻은 결론입니다.

## 1. 인자 처리
- [확인 E3/E4] `argc < 2`(`cmp w0,#1; b.gt`)이면 `puts("usage: tagcode <text>")`를 호출하고 1을 반환합니다(`mov w0,#1`).
- [확인 E4] 그 외에는 `argv[1]`만 읽습니다(`ldr x9,[x1,#8]`). argv[2] 이후는 어디에서도 참조하지 않습니다.
- [추론] 반환값이 그대로 프로세스 종료 코드가 됩니다. usage 메시지는 stdout으로 나갑니다(`puts`).

## 2. 해시 계산 (E4 0x10000048c–0x1000004b4)
- [확인] 초기값 `h = 0x1234`입니다.
- [확인] 바이트를 `ldrb`로 읽으므로 부호 없는 8비트 값입니다. NUL을 만날 때까지 반복합니다.
- [확인] 바이트 하나 `c`마다 다음을 수행합니다.
  `w11 = c - h; h = w11 + (h << 5); h = h ^ (h >> 7)` (32비트 w 레지스터, `LSR`은 논리 시프트)
- [추론] 위 식은 `h = h*31 + c` 다음에 `h ^= h >> 7`을 하는 것과 같습니다. 모두 uint32 모듈러 연산입니다.
- 참고: E3 의사코드에는 이 산술이 나타나지 않습니다(문자열 길이만 세는 루프로 보임). 그래서 이 부분은 E4 어셈블리를 근거로 했습니다.

## 3. 코드 값
- [확인 E4] 문자열이 비어 있지 않으면 `code = h % 10000`입니다.
  - [추론] `umull` × `0xd1b71759` 다음 `lsr #45`는 `h/10000`을 곱셈으로 바꾼 컴파일러 최적화입니다. 이어지는 `msub`(`#0x2710` = 10000)로 나머지를 구합니다.
- [확인 E4] 빈 문자열이면(`cbz w11` → 0x1000004e8) `code = 0x1234 = 4660`입니다. 모듈러를 적용하지 않습니다(4660 < 10000이므로 결과는 같음).

## 4. 등급
- [확인 E4] 빈 문자열이면 등급은 `x8` 초기값, 즉 0x56e `"SILVER"`입니다.
- [확인 E4] 비어 있지 않으면 `t = code >> 3`으로 놓고 판정합니다.
  - `t > 0x464`(1124) → `"PLATINUM"`
  - 아니고 `t > 0x36a`(874) → `"GOLD"`
  - 아니고 `code > 0xf9f`(3999) → `"SILVER"`, 그 외에는 `"BRONZE"`(`csel ... hi`)
- [추론] 임계값을 code 기준으로 바꾸면 PLATINUM은 code ≥ 9000, GOLD는 7000 ≤ code < 9000, SILVER는 4000 ≤ code < 7000, BRONZE는 code < 4000입니다. 빈 문자열(4660)도 같은 규칙으로 SILVER가 나오므로 결과가 일관됩니다.

## 5. 출력
- [확인 E4] `printf("code=%04u grade=%s\n", code, grade)`를 호출하고(`stp x9,x8,[sp]`로 가변 인자 전달) 0을 반환합니다.
  - 참고: E3 의사코드에는 printf 인자가 없습니다. Darwin arm64에서는 가변 인자를 스택으로 넘기기 때문에 디컴파일러가 놓친 것이고, 인자는 E4에서 확인했습니다.
- [추론] 출력되는 code는 0–9999이므로 `%04u`에 따라 항상 4자리로 0 패딩됩니다.
